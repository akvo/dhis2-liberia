# DHIS2 Water Facility Tracked Entity Setup Guide

This guide walks through creating a Tracked Entity in DHIS2 to track water facilities, with integration to Sunbird RC for ID generation.

## Architecture Overview

```
DHIS2 (Primary Data Entry)
         │
         │ 1. Create Water Facility
         │    (osid & wfId empty)
         ▼
      Adapter
         │
         │ 2. Fetch new records from DHIS2
         │ 3. Send to Sunbird RC
         ▼
    Sunbird RC
         │
         │ 4. Generate osid & wfId
         ▼
      Adapter
         │
         │ 5. Update DHIS2 with osid & wfId
         ▼
DHIS2 (Updated with IDs)
```

**Key Points:**
- DHIS2 is the primary data entry point
- `osid` and `wfId` are initially empty (optional fields)
- Sunbird RC generates these IDs
- Adapter syncs the generated IDs back to DHIS2

## Prerequisites

- DHIS2 instance running (http://localhost:9090)
- Admin access (default: `admin` / `district`)

## Adapter Workflow

### 1. Fetch Pending Records from DHIS2

```bash
# Get all records with syncStatus = PENDING (or osid is empty)
curl "http://localhost:9090/api/trackedEntityInstances?ou=<ORG_UNIT>&program=<PROGRAM_ID>&filter=<SYNC_STATUS_ATTR_ID>:eq:PENDING" \
  -u admin:district
```

### 2. Transform and Send to Sunbird RC

```json
{
  "geoCode": "qqgtest01",
  "waterPointType": "Protected dug well",
  "location": {
    "county": "Jawa Timur",
    "district": "Surabaya",
    "community": "Gubeng",
    "coordinates": {
      "lat": -7.2654,
      "lon": 112.7521
    }
  },
  "extractionType": "Manual",
  "pumpType": "Afridev"
}
```

### 3. Sunbird RC Response

```json
{
  "result": {
    "WaterFacility": {
      "osid": "1-1c8618cb-70c2-4149-8400-211c486fec6a"
    }
  }
}
```

Then fetch the created record to get `wfId`:
```json
{
  "osid": "1-1c8618cb-70c2-4149-8400-211c486fec6a",
  "wfId": "WF-JAW-SUR-PDW-2CD027",
  ...
}
```

### 4. Update DHIS2 with Generated IDs

```bash
curl -X PUT "http://localhost:9090/api/trackedEntityInstances/<TEI_ID>" \
  -H "Content-Type: application/json" \
  -u admin:district \
  -d '{
    "attributes": [
      {"attribute": "<SUNBIRD_OSID_ID>", "value": "1-1c8618cb-70c2-4149-8400-211c486fec6a"},
      {"attribute": "<WF_ID_ID>", "value": "WF-JAW-SUR-PDW-2CD027"},
      {"attribute": "<SYNC_STATUS_ATTR_ID>", "value": "SYNCED"}
    ]
  }'
```

## Sync Flow Summary

```
┌─────────────────────────────────────────────────────────────────┐
│                       Adapter Sync Flow                         │
├─────────────────────────────────────────────────────────────────┤
│  1. Query DHIS2 for records where syncStatus = PENDING          │
│  2. For each record:                                            │
│     a. Transform DHIS2 data → Sunbird RC format                 │
│     b. POST to Sunbird RC /api/v1/WaterFacility                 │
│     c. Get osid from response                                   │
│     d. GET /api/v1/WaterFacility/{osid} to fetch wfId           │
│     e. PUT to DHIS2 with osid, wfId, syncStatus=SYNCED          │
│  3. Handle errors: set syncStatus=FAILED                        │
└─────────────────────────────────────────────────────────────────┘
```
